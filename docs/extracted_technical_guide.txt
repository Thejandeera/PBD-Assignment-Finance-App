1. Purpose of the Project and How to Use This Guide
What we are building. Kavindu Silva (25, junior engineer in Colombo) earns roughly LKR 1.6 million a year from four sources, yet has only LKR 11,200 saved. He cannot say where his money goes and wants a MacBook Pro M4 (about LKR 490,000) within 12 months. Four earlier tools failed him because they were too manual, too rigid, single-currency or unpleasant to open daily.
Our app must do two things: (1) reveal what he really earns and where it goes, and (2) make progress toward the MacBook goal feel real. Everything we build is judged against that.
Grading reminder: marks reward problem understanding, architecture and the live demo, not feature count. A focused app with clean MVVM beats a feature-heavy app with structural weaknesses.

5.4 Create Firestore security rules and indexes
Owner: Member A. Rules are a mandatory deliverable. Missing rules score zero for the Firebase criterion.
In the project root create firestore.rules (full text in Appendix A).
Principle: a signed-in user may read and write only documents under `users/{their own uid}`. Everything else is denied by default.
Add validation: amount must be a number, expense amount must be greater than 0, currency must be one of LKR/USD/USDT, source and type must be allowed values.
Test in the console: Firestore → Rules → Rules Playground. Simulate (1) an authenticated read of your own path – allowed; (2) a read of another uid – denied; (3) an unauthenticated read – denied.
Deploy: either paste into Firestore → Rules → Publish, or with the CLI run firebase init firestore once, then firebase deploy --only firestore:rules,firestore:indexes.
Create firestore.indexes.json for composite indexes (Appendix A). If a query needs an index, Logcat prints an error containing a link; open it to create the index, then copy it into the JSON file.
Commit both files to the repository root and mention them in the README.
Do not leave the “test mode” rule (allow read, write: if true) in the project. It exposes all data and will be penalised.
5.5 Authentication flow
A builds AuthRepository (signUp, signIn, signOut, currentUserFlow) around FirebaseAuth.
AuthViewModel validates email format and password length (6+), exposes StateFlow<AuthUiState> (Idle, Loading, Success, Error) and never touches the UI.
C’s Login and Register screens collect the state, show inline errors and navigate on success.
Navigation start destination: Dashboard if currentUser != null, otherwise Login.
On sign-up create the user profile document users/{uid} with name, email, default rates and a default goal.
Map Firebase exceptions to friendly messages (wrong password, user not found, email already in use, network error).
MERMAID – login request flow
5.6 Hilt dependency injection and MVVM base
Add the Hilt Gradle plugin, KSP and dependencies (Appendix B).
Create ClarityApp : Application annotated with @HiltAndroidApp and register it in the manifest.
Annotate MainActivity with @AndroidEntryPoint (single-activity architecture).
Create AppModule that provides FirebaseAuth, FirebaseFirestore, the Room database and DAOs, and binds repository interfaces to implementations.
Annotate every ViewModel with @HiltViewModel and @Inject constructor(...).
In Composables obtain ViewModels with hiltViewModel() only – never ViewModel() constructors.
Expose state as StateFlow (private MutableStateFlow, public read-only asStateFlow()). Collect in UI with collectAsStateWithLifecycle().
Launch all asynchronous work in viewModelScope.
Three-question review for every pull request: (1) Is there any if/calculation logic inside a Composable beyond display? (2) Does any Composable import a repository, Firestore or Room class? (3) Is any MutableStateFlow public? If yes to any, request changes.
5.7 Real-time listeners (dashboard and lists)
Wrap addSnapshotListener in a callbackFlow and always call awaitClose { registration.remove() } to avoid leaks.
Query only the visible month using the denormalised month field (for example "2026-10").
Repository returns Flow<List<T>>; ViewModel uses combine to merge income, expense and goal flows into one summary.
Add .catch { } so listener errors become UiState.Error instead of crashes.
Use SnapshotListenOptions or metadata (isFromCache) to show a small “offline – showing saved data” indicator.
MERMAID – dashboard real-time updates
5.8 Offline support with Room and Firestore persistence
Firestore offline persistence is on by default on Android; confirm it in FirebaseFirestoreSettings and keep it enabled.
Add Room entities mirroring the domain models (income, expense, goal, savings) plus DAOs that return Flow.
Repository pattern: the UI reads from Room; Firestore listeners write incoming changes into Room; writes go to Firestore (queued automatically when offline).
Never block the UI on network: show cached data immediately, then update.
Test: enable airplane mode, add an expense, confirm it shows, disable airplane mode and confirm it reaches Firestore.
Show a non-blocking banner when offline (see C’s OfflineBanner).

5.9 Git workflow and merge conflicts
Branch names: feature/<area>-<task>, fix/<bug>, docs/<section>. Never commit directly to main.
Commit messages: feat:, fix:, docs:, refactor:, test: prefix plus a short sentence.
Open a pull request into develop; one teammate reviews using the three-question check.
Pull develop into your branch daily (git pull origin develop) to keep conflicts small.
If a conflict occurs: open the file, keep both intended changes, remove markers (<<<<<<<, =======, >>>>>>>), build, then git add and git commit.
Merge develop into main only for milestone builds (end of week 2, 3 and final).
5.10 Build and validate the APK
Run the app on an API 26 emulator and a real device; test sign-up, add data, airplane mode and sign-out.
Debug APK: Build → Build Bundle(s)/APK(s) → Build APK(s). It is acceptable if connected to the live Firebase project.
Release APK (optional, stronger): Build → Generate Signed Bundle / APK → APK, create a keystore, store it outside the repository and keep the password safe.
Copy the APK to a different phone and install it from scratch to prove it installs.
Confirm the app talks to the live Firebase project (data appears in the console). Local emulator configuration is not accepted.

Appendix A – Firestore Rules and Indexes
firestore.rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
 
    function signedIn() { return request.auth != null; }
    function isOwner(uid) { return signedIn() && request.auth.uid == uid; }
 
    match /users/{uid} {
      allow read, write: if isOwner(uid);
 
      match /incomes/{id} {
        allow read, delete: if isOwner(uid);
        allow create, update: if isOwner(uid)
          && request.resource.data.amount is number
          && request.resource.data.currency in ['LKR', 'USD', 'USDT']
          && request.resource.data.source in ['SALARY', 'FREELANCE', 'ADSENSE', 'CRYPTO']
          && request.resource.data.status in ['RECEIVED', 'PENDING'];
      }
 
      match /expenses/{id} {
        allow read, delete: if isOwner(uid);
        allow create, update: if isOwner(uid)
          && request.resource.data.amount is number
          && request.resource.data.amount > 0
          && request.resource.data.type in ['COMMITTED', 'DISCRETIONARY']
          && request.resource.data.paymentMethod in ['CARD', 'CASH', 'SECONDARY'];
      }
 
      match /{document=**} {
        allow read, write: if isOwner(uid);   // recurring, goals, savings, categories
      }
    }
  }
}

Why these indexes: the monthly lists for Home, Insights and Income filter by month and sort by date; the Waiting for payment list filters by status; the crypto year-to-date position filters by source and a date range; the Insights filter chips add type.

// Generic UI state
sealed interface UiState<out T> {
    data object Loading : UiState<Nothing>
    data object Empty : UiState<Nothing>
    data class Success<T>(val data: T) : UiState<T>
    data class Error(val message: String) : UiState<Nothing>
}
 
// Firestore listener as Flow (data layer)
fun <T> Query.asFlow(mapper: (QuerySnapshot) -> List<T>): Flow<List<T>> = callbackFlow {
    val reg = addSnapshotListener { snap, err ->
        if (err != null) { close(err); return@addSnapshotListener }
        if (snap != null) trySend(mapper(snap))
    }
    awaitClose { reg.remove() }
}
 
// ViewModel pattern
@HiltViewModel
class DashboardViewModel @Inject constructor(
    private val income: IncomeRepository,
    private val expenses: ExpenseRepository,
    private val goals: GoalRepository
) : ViewModel() {
    private val _state = MutableStateFlow<UiState<Summary>>(UiState.Loading)
    val state: StateFlow<UiState<Summary>> = _state.asStateFlow()
 
    init {
        viewModelScope.launch {
            combine(income.observeMonth(month()), expenses.observeMonth(month()), goals.observeGoal()) { i, e, g ->
                Summary.from(i, e, g)
            }.catch { _state.value = UiState.Error(it.message ?: "Something went wrong") }
             .collect { _state.value = UiState.Success(it) }
        }
    }
}
 
// Composable: collects state only
@Composable
fun DashboardScreen(vm: DashboardViewModel = hiltViewModel()) {
    val state by vm.state.collectAsStateWithLifecycle()
    when (val s = state) {
        UiState.Loading -> LoadingState()
        UiState.Empty -> EmptyState("Log your first expense with +")
        is UiState.Error -> ErrorState(s.message)
        is UiState.Success -> DashboardContent(s.data)
    }
}
Appendix C – Glossary
Term
Meaning in this project
Committed expense
Fixed or unavoidable cost such as rent, utilities, gym, subscriptions
Discretionary expense
Spending by choice, such as coffee, delivery, shopping, fun
Rate snapshot
The LKR exchange rate saved with each USD or USDT income at transfer time
Pending invoice
Freelance payment not yet received; excluded from actual monthly income
Required monthly saving
(Target − saved) divided by months left until the deadline
Vertical slice
One feature built across data, repository, ViewModel and UI by one member
UiState
Sealed class describing Loading, Empty, Success or Error for a screen
Snapshot listener
Firestore feature that pushes changes in real time
SHA-1
Signing fingerprint registered in Firebase so sign-in works on each developer machine
